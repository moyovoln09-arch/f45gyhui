# Тестер прокси-ссылок (VLESS, Trojan, Hysteria2)

Этот скрипт позволяет тестировать и ранжировать прокси-ссылки VLESS, Trojan и Hysteria2 на Linux. Он оценивает стабильность, скорость YouTube и скорость скачивания торрентов.

## Особенности

- **Поддержка протоколов:** VLESS (TCP, WS, gRPC, Reality), Trojan (TLS, gRPC), Hysteria2.
- **Ранжирование:** Сортировка ключей по совокупному баллу (стабильность 40%, YouTube 30%, Torrent 30%).
- **Рандомизация:** Возможность перемешивания ключей перед тестированием и перемешивания нод в экспортируемом конфиге.
- **Экспорт в Sing-box:** Генерация готового клиентского конфига `sing-box` с поддержкой балансировки нагрузки.
- **Игровой режим Hysteria2:** По умолчанию установлена скорость 200 Мбит/с для Hysteria2, что обеспечивает отличную производительность в играх.
- **Равномерное распределение:** В экспортированном конфиге по умолчанию используется outbound типа `loadbalance` со стратегией `random`, что позволяет равномерно распределять трафик между серверами.

## Требования

Для работы скрипта необходимы следующие системные пакеты:
- `sing-box`
- `aria2c`
- `yt-dlp`

Скрипт может попробовать установить их автоматически при использовании флага `--auto-install`.

## Использование

1. Подготовьте файл с ключами (по одному на строку).
2. Запустите скрипт:

```bash
python3 proxy_tester.py --keys keys.txt --export-singbox config.json
```

### Основные аргументы:

- `--keys`: Путь к текстовому файлу с ссылками (vless://, trojan://, hy2://).
- `--top`: Количество лучших ключей для вывода и экспорта (по умолчанию 5).
- `--timeout`: Время тестирования для каждой категории (по умолчанию 30 секунд).
- `--export-singbox`: Путь для сохранения сгенерированного конфига sing-box.
- `--shuffle`: Перемешать ключи перед началом тестирования.
- `--no-shuffle-output`: Отключить перемешивание нод в экспортируемом конфиге (ноды будут идти в порядке убывания балла).
- `--auto-install`: Попробовать автоматически установить недостающие зависимости.

## Принцип рандомизации

Чтобы избежать ситуации, когда большинство пользователей выбирает первый ключ в списке, скрипт по умолчанию перемешивает лучшие ноды в сгенерированном конфиге. Присваиваемые теги (`node-1`, `node-2` и т.д.) не отражают их реальный рейтинг производительности.

Кроме того, основным исходящим соединением в конфиге является `random` (loadbalancer), который выбирает случайную ноду для каждого нового соединения, обеспечивая равномерную нагрузку на сервера.
